## Project readiness

- [x] Implement a Twitch-connected interactive experience built with Codex.

- [x] Provide a labeled simulator, usable SDK and independent minimal example.

- [ ] Confirm the final project consistently runs as described and shown in the recording.
- [ ] Confirm work was newly created during the submission period (officially opens 23 October 2026, 10 AM PT).

## Eligibility and access — owner action

- [ ] Confirm every entrant is at least 18 or local age of majority, whichever is older; check residency, sanctions, employment/conflict exclusions and all official terms. Organizations are excluded; eligible individuals and teams may enter.
- [ ] Register on Devpost. For a team, appoint an authorized representative and ensure teammates accept invitations.
- [ ] Provide a GitHub/GitLab/Bitbucket source repository URL with all assets and instructions. A private repository must use an allowed provider and be shared with the judging address given in the rules. Copy that address from the official page rather than relying on a redacted scrape.
- [ ] Provide judges free working-project access through the end of judging; do not require payment.
- [ ] Complete the English description of features, functionality and actual Codex usage.
- [ ] Type **`/status` in the main Codex build thread** and paste the real session ID into the form, per the official FAQ.

## Video — owner action

- [ ] Record an English demo **under three minutes**, including the actual project working on Twitch and how it was built with Codex.
- [ ] Show actual gameplay, real crew participation, a visible consequence and one reliability demonstration (label synthetic conditions).
- [ ] Exclude private terminal codes, credentials, tokens and unlicensed music/third-party material.
- [ ] Upload the video publicly to **YouTube** and include its link in the form, as required by the official rules.
- [ ] Review `DEMO_SCRIPT.md` and `DEVPOST_DRAFT.md` for accuracy. Remove placeholders only when the corresponding evidence exists.
